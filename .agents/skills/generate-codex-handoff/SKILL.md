# 生成 Codex 任务交接

整理当前任务的完整有效上下文，使新的 Codex 对话能够直接继续工作，不需要用户重新解释。

本 Skill 默认只读，不修改代码或项目文件。

## 信息整理

结合当前对话和工作区实际状态整理内容。必要时可以只读检查：

- 适用的 `AGENTS.md`；
- `git status` 和相关 diff；
- 当前任务涉及的代码、配置和文档；
- 已执行的测试、命令及其结果。

只检查与当前任务直接相关的内容，不要扫描整个项目。

区分以下状态：

- 已经实际完成的修改；
- 已经确认但尚未实现的方案；
- 仅讨论过的候选思路；
- 尚未确认的信息。

无法确认的内容应标记为“待确认”，不得猜测。排除无关支线、已经结束的临时问题、重复讨论和敏感信息。

## 输出内容

生成一份可直接粘贴到新 Codex 对话中的提示词，包含：

1. 当前目标；
2. 已经完成的修改；
3. 当前代码结构；
4. 关键设计决策；
5. 还没完成的问题；
6. 下一步应该做什么。

其中：

- “当前目标”说明最终要解决的问题和当前阶段。
- “已经完成的修改”写明修改过的文件、主要行为和验证结果。
- “当前代码结构”只列与任务相关的目录、文件、类和调用关系。
- “关键设计决策”记录已确认的方案、约束及选择原因。
- “还没完成的问题”包含待实现内容、已知缺陷、阻塞项和待确认信息。
- “下一步”按照优先级给出可以直接执行的具体动作。

如果任务不涉及代码，在“当前代码结构”中明确说明，不要虚构内容。

## 输出格式

只输出一个完整的 Markdown 代码块，方便用户直接复制。

使用下面的结构：

```text
你正在继续处理以下任务。请先理解上下文，在现有进度上继续，不要重复已经完成的工作。

## 1. 当前目标

...

## 2. 已经完成的修改

...

## 3. 当前代码结构

...

## 4. 关键设计决策

...

## 5. 还没完成的问题

...

## 6. 下一步应该做什么

...

## 工作要求

- 先检查现有实现和项目规则，再继续修改。
- 保留已经确认的设计决策。
- 不要重复已经完成的工作。
- 遇到上下文中标记为“待确认”的内容时，先核实再处理。
```

内容应简洁但完整，保留新对话继续任务所必需的文件路径、参数、约束、错误信息和验证结果，避免复述整段聊天记录。
